# Task 3 — Implement `tools/gen_trexio_py.py` (the Python emitter)

**Track:** A · **Depends on:** task-1 (the `api/trexio_gen.py` target + `_base`) and task-2 (the
shared model). If those are done in any order, you only need both.
**Why it matters:** this is the actual "generate `api/trexio.py`'s surface from trex.json +
the C header" step. It replaces the hand-kept 862 wrappers with the same surface, generated.

## Objective
`tools/gen_trexio_py.py` reads the shared model (`tools/trexio_api_model.py`), the installed
`trexio.h`, `third_party/trex.json`, and `tools/required_api.names`; classifies each required
name; and writes `api/trexio_gen.py` **function-for-function identical to the copy that task-1
left in place** (bodies + symbols; docstrings per D3 — compact-but-full).

## Notes / gotchas
- If a symbol in `required_api.names` classifies to a family, but the Python template for that
  family needs a dim-token resolution (e.g. `mo_coefficient` requires `mo.num` **and** `ao.num`),
  the dims come from `third_party/trex.json` (`locate_group_var` → `data[group][var][1]` → the
  dims list). If a dim token doesn't resolve to a known `read_<g>_<v>`, **halt** (`TODO:`) — do
  not guess.
- `STRARR_R` reads (`read_metadata_code`, `read_nucleus_label`, …) call the *sibling*
  `read_X_num` for the count. That sibling is also generated in the same file; the ordering in the
  generated module does not matter (Python resolves at call time, not def time).
- The `LOW_DIM_FN` map in `tools/trexio_api_model.py` (used by `gen_binding.py`'s `e_STR_R`) is a
  C++-side concern; the Python side just needs the `_low` symbol (already in `required_api.names`)
  and the `read_X_num` call. Don't mix the two.
